正文

使用 Perfetto 分析问题跟使用 Systrace 分析问题的步骤是一样的：

  1. 先抓取 Perfetto 文件
  2. 在ui.perfetto.dev 中打开 Trace 文件进行分析或者使用命令行来进行分析

这篇文章就简单介绍一下使用 Perfetto 抓取 Trace 文件的方法，个人比较推荐使用命令行来抓取，不管是自己配置的命令行还是官方的命令行抓取工具，都非常实用。

1. 使用命令行来抓取 Perfetto（推荐）

基本命令 - adb shell perfetto

连接已授权 USB 调试的 Android 设备后，可以用设备上的 /system/bin/perfetto 抓取。下面是轻量模式示例；运行后立即操作手机，在这 20 秒内复现场景，命令返回后再执行 adb pull。

这个示例录制 20 秒，使用 64 MB 环形缓冲区；写满会覆盖旧事件，因此不保证保留完整的 20 秒。后面的参数是 atrace 类别，支持情况随系统变化，可用 adb shell atrace --list_categories 查看。轻量模式主要覆盖 ftrace/atrace，不会因为写了 memory 就得到完整堆快照，也不会自动启用 FrameTimeline 或调用栈采样。

若要录入自己 App 的 android.os.Trace / ATrace 埋点，在类别列表之前增加 --app com.example.app，并替换为目标包名；gfx、view 等系统类别不能替代 App 选择。采集完成后检查命令是否成功、文件是否包含目标时段与事件，再在 Perfetto UI 打开。输出路径是设备路径，adb pull 后的文件才在电脑上。

进阶命令 adb shell perfetto with config file

这里就是 Perfetto 与 Systrace 不同的地方，Perfetto 可以抓取的信息非常多，其数据来源也非常多，每次都用命令行加一大堆配置的话会很不方便。这时候我们就可以使用一个单独的 配置文件（Config），来存储这些信息，每次抓取的时候，指定这个配置文件即可。

注意事项

  • 连接与版本：adb devices 应显示目标为 device，不是 unauthorized 或 offline。多设备时给原始 adb 命令加 -s 设备序列号；给官方脚本加 --serial 设备序列号。记录系统版本、设备端 Perfetto 版本及最终配置。
  • 提前停止：直接运行 adb shell perfetto 时，Ctrl+C 的传递不可靠，不能把电脑端退出当作设备端已正常收尾。可使用官方脚本处理停止，或先进入交互式 adb shell，再在设备 shell 中运行 Perfetto。按设定时长正常完成的例子不需要额外中断。
  • SELinux 限制： Android 12 及以上设备可把配置文件放在/data/misc/perfetto-configs，不要假设perfetto能直接读取/data/local/tmp里的配置文件。

3. 使用手机上的开发者工具来抓取

无法连接电脑，或测试场景不适合插 USB 时，可以使用系统跟踪应用。该入口从 Android 9（API 28）提供；Android 10+ 默认保存 Perfetto 格式，Android 9 保存 Systrace 格式。OEM 可能调整或隐藏入口，不能保证所有手机具有相同选项。

启动系统跟踪应用

  1. 启用开发者选项：先确保你的设备已经启用了开发者选项。如果你的设置里面没有开发者选项，你需要在关于手机那里，找到编译编号，然后连续点击 7 次，就可以打开开发者选项。

  2. 打开开发者选项：在设置菜单中找到并打开开发者选项。

  3. 启动系统跟踪：在开发者选项中向下滚动直到找到”系统跟踪（System Trace）”或类似的选项。点击它，将打开系统跟踪应用。

下面是原文设备的系统跟踪界面，供辨认入口；具体设置以当前设备为准。

常见设置包括要采集的类别、每 CPU 缓冲区大小、可调试应用和快捷设置磁贴。支持“长时间跟踪”的设备还可设置最大文件大小与最大时长；普通模式是滚动缓冲区，不是任意固定秒数的完整录制。应用管理输出文件，再通过保存通知、文件应用或分享入口导出，通常没有自选输出路径的选项。

启动和停止跟踪

配置好所有需要的参数后，你可以通过点击”录制跟踪记录”按钮来启动跟踪。再次点击”录制跟踪记录”按钮就可以结束抓取，完成抓取后，通常会有一个提示告诉你抓取已经完成，并提供查看或分享跟踪文件的选项。就可以将跟踪文件导出到电脑上，使用 Perfetto 网页 UI 进行更深入的分析。

4. 使用网页端来抓取

2024 年写初稿时，我觉得网页抓取有点迷：有时连不上，有时又提示 ADB 被占用。所以我更习惯用命令行采集，网页则用来配 Config。下面保留旧截图，并补充当前连接方式。

版本更新：v49.0（2025-01-06）的官方变更记录确认重写了录制页面。本次只读查看的 stable UI 为 v58.3-11fbaed83，已提供多种连接方式；这不代表每台设备的连接稳定性都经过验证。

在 Record new trace 选择 Android 平台和连接方式。当前 UI 的 WebUsb 需要浏览器支持并独占设备 USB 接口，可能与本地 adb server 冲突；ADB + WebSocket 使用本地桥接程序，可以与其他 adb 工具共存。按页面提示连接并在手机确认授权，再配置和开始录制。不要因为旧截图提到 kill 就无条件结束所有 ADB 会话；也可以只在网页生成配置，用命令行采集。

旧版入口叫 Recording command；本次查看的 v58.3 UI 中叫 Cmdline instructions，分别列出 Shell 命令和 textproto 配置。可复制或下载配置，供后续命令行重复使用。

按问题选择数据源，不建议照旧图的“可以都选上”批量全开。UI 卡顿通常需要 CPU 调度、相关 atrace 类别与目标 App；FrameTimeline 另需 Android 12+ 的 android.surfaceflinger.frametimeline 数据源。Logcat 是可选日志源，并非每个问题都需要。采得越多，开销、数据量和丢失风险也越高。

需要调用栈时，再启用 Stack sampling。它依赖 traced_perf、设备支持和目标进程权限；user 系统通常只允许 profileable 或 debuggable 目标，不能照图就采到任意系统进程。当前官方 CPU profiling 教程按 Android 15+ 给出新配置流程，旧设备需匹配其采集组件版本。采样是离散观测，不是记录每次函数调用；频率、栈展开和符号缺失都会影响结果。

至于其他的有啥用，可以自己探索，后续的 Perfetto 也会介绍到每个部分和他在 Trace 上的呈现，帮助大家更快入手 Perfetto。
