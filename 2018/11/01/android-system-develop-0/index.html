不管是 Android App 开发工程师还是 Android 系统开发工程师，对 Android 系统有一定的了解是很有必要的，正好我这几天在家里搭建了个开发环境，把过程分享出来，有需要的人可以看一下。

大概的步骤包含下面几个：

  1. 安装 Ubuntu 系统
  2. 配置 Ubuntu 系统
  3. 安装必备的软件
  4. 配置网络访问环境 (可选)
  5. 下载 AOSP 代码
  6. 配置编译环境并编译 Pixel 的代码
  7. 刷机
  8. 修改和编译 Framework 、Service、Res

版本说明（2026-10-13 核查）：原文是 2018 年的环境记录。截图可见 Ubuntu 18.04.1、PLATFORM_VERSION_CODENAME=Q、aosp_sailfish-userdebug，但未保存完整 manifest，不能重建当时的 master 提交。旧 Pixel/刷机部分作为历史流程保留；新增示例固定 Android 16 的 android-16.0.0_r1、Ubuntu 22.04 x86_64、Cuttlefish x86_64，不代表最新发布，也不是给初代 Pixel 刷 Android 16 的教程。

原来建议的“512 GB SSD + 一台 Pixel”要分情况看。新建现代 AOSP 工作站时，可以参考当前官方环境要求：64 位 x86 Linux、至少 400 GB 可用空间和 64 GB RAM。磁盘标称 512 GB 不等于还有 400 GB 可用，多源码树和输出会继续占空间；这些是工作站规划基线，不是所有旧版本的硬性门槛。仅阅读源码可以少配一些；运行本文的 Cuttlefish 示例还需要可用的 KVM，真机不是必需品。

安装 Ubuntu 系统

原文使用 Ubuntu 18.04，它的常规安全维护已于 2023 年 5 月结束，扩展维护另有条件，见 Ubuntu 生命周期。新示例选用 Ubuntu 22.04 LTS，而不是继续使用那条旧 18.04.1 ISO 镜像链接。

  1. 从 Ubuntu 22.04 官方发行目录获取 amd64 安装镜像，按目录中的校验信息检查下载。
  2. 制作启动 U 盘，并在分区前备份原系统数据。
  3. 安装到准备好的 Linux 主机；虚拟机也可以使用，但要分配足够磁盘和内存，运行 Cuttlefish 时还需向客体提供 KVM/嵌套虚拟化。虚拟机里能编译，不代表一定能运行虚拟设备。

下面是我当时的桌面。当前 AOSP 主机要求以 Linux 为准，不能把本文命令直接当成 macOS 或 Apple Silicon 的原生构建流程。

配置 Ubuntu 系统

输入法和编辑器按个人习惯选择。Vim 可用 sudo apt install vim 安装；adb、fastboot 可通过 Android Studio SDK Manager 或官方 SDK Platform-Tools获取。构建 AOSP 后也会得到主机工具，使用时先确认终端实际找到的是哪一份，避免混用旧工具：

Linux 真机连接还要完成 USB 调试授权和设备访问权限配置；能列出设备后，再进行后面的部署。

安装必备的软件

我当时列的 VS Code、Android Studio、Meld 是编辑/比较工具；Wine、WPS 和搜狗输入法是自己的桌面使用习惯，都不是 AOSP 编译依赖。按自己需要安装即可，系统构建依赖见后面的章节。

配置网络访问环境 (可选)

根据本地环境准备稳定的源码访问方式。Repo 自身的下载源与 AOSP manifest/项目镜像是不同入口，只替换 manifest 地址未必解决所有连接问题。

配置编译环境并编译 Pixel 的代码

这一节区分两个目标：原图中的初代 Pixel sailfish 是历史案例；新增命令编译 Cuttlefish。产品名、源码、专有二进制和输出必须匹配，不能把两个目标的步骤拼起来执行。

配置编译环境

安装jdk

原文安装 openjdk-8-jdk 的做法不能通用于现代 AOSP。本文固定的 Android 16 源码由构建系统选择 Java 工具链；envsetup.sh 设置 ANDROID_JAVA_HOME/JAVA_HOME，不要强行覆盖成系统 JDK 8。旧版本需要什么 JDK，应按对应分支要求配置。编译 AOSP 也不是用 Android Studio 自带的 Gradle 去构建整棵源码树。

安装相关依赖

在本文选定的 Ubuntu 22.04 环境中，参考官方 Linux 依赖清单：

这里修正了原文的 lib32z-dev，不再照搬旧 lib32ncurses5-dev 等包名。其他发行版或旧 Android 分支应使用自己的依赖清单，不能混装后假定结果相同。

下载 Pixel 的驱动

历史 Pixel 流程：专有硬件支持文件要与设备代号和 Android 构建号匹配。正式版本驱动下载页按设备与构建号列出文件；不能把旧 blobs-preview 页中的“最新预览驱动”与任意源码混用。按随包说明在对应源码根目录提取，并阅读许可条件；文件通常进入 vendor/。原文没有记录下载包的完整版本，因此不能据旧截图补造它的配套标签。

修改和编译 Framework 、Service、Res

先完成同一源码树、同一目标的完整构建，再做增量修改。目录名不等于模块名，模块编译完成也不一定已经生成可刷镜像。

修改代码 IDE

java代码

Java/Kotlin 可以用 Android Studio 编辑。整棵 AOSP 不是普通 Gradle 项目，代码索引和依赖可参考分支中的 AIDEGen或该分支支持的 IDE 工程生成方式；编辑器能打开文件不代表能正确解析所有平台符号。

c/cpp代码

C/C++ 可继续用熟悉的编辑器，如 VS Code。Source Insight、Eclipse 是原文当时的选择，不是系统构建要求；补全和跳转需要与实际编译配置匹配。
