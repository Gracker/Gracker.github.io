Android 12 source was released in 2021. My test phone at the time was a Pixel 3 XL. This article keeps that hands-on record and pins the release-build example to android-12.0.0_r3. Verify version mappings in the AOSP tags/build numbers table.

Compiling the code locally offers several advantages:

  1. Direct Debugging: You can flash the build onto a physical device for local debugging and import the code into Android Studio.
  2. Userdebug Builds: These provide additional debugging capabilities. adb root/remount still depends on adbd, AVB/verity, partition layout, and build configuration. A userdebug build does not make every directory writable or replace an app’s own debugging permissions.
  3. Studying the System: You can enable more system debug logs, add your own, and change the code to see how it works.

Historical version note (reviewed 2026-10-14): Android 12 r3, Pixel 3 XL, and the 2021 screenshots are references for studying an old release, not recommendations for current devices or production firmware. The r3 security patch level is 2021-10-05. Some original screenshots instead show the master development branch: Tiramisu/AOSP.MASTER does not prove an Android 12 r3 build. They are retained with explanations below.

For current AOSP, use the download and build guides. In a separate checkout, the documented android-latest-release branch follows current releases; it does not pin Android 12:

This is the current guide’s Cuttlefish virtual-device example, not a Pixel 3 XL flashing target. Its product-release_config-variant format differs from Android 12’s product-variant. Check availability in the actual checkout and save repo manifest -r output to identify revisions. Do not mix vendor files across releases. The USTC mirror limits concurrency to four, so do not copy the official-server -j8 setting there.

For source browsing alone, use cs.android.com. Reproducing this article requires:

  1. A matching Pixel 3 XL (crosshatch) whose bootloader can be unlocked. Pixel 3 is blueline and is a different target. SIM unlocking does not imply bootloader unlocking; “Pixel 3 or newer” does not mean all later models can run Android 12.
  2. An x86-64 Linux host with a case-sensitive filesystem and sufficient storage/RAM. The historical host screenshot shows Ubuntu 18.04.6. The old 32GB suggestion was contemporary experience, not a current guarantee; swap is not equivalent RAM. Current official requirements specify at least 400GB free storage and 64GB RAM. Old-branch resource needs still depend on target and parallelism.

1. Downloading the Code

At the time, downloading from Google’s servers in China could be painfully slow; even .repo could get stuck. That is why I used the USTC AOSP mirror as an alternative here; the official download guide remains the reference. Follow mirror protocol and concurrency rules. Its current documentation uses HTTPS, replacing the old git:// URLs in this article.

Download into the Linux filesystem you will build from. Running Git/Repo commands on WSL2 or macOS does not establish a validated Android 12 build/USB-flashing environment. Do not assume Windows-mounted or case-insensitive directories meet source-tree requirements.

2. Downloading Drivers (Proprietary Binaries)

Physical-device builds need matching proprietary binaries. These can include HALs, userspace libraries, vendor images, and firmware; they are not all driver source code. Match the device, source Build ID, and vendor instructions regardless of the presence of -b. These files are also distinct from Google Apps or Pixel Launcher.

3. Compiling the Code

This target uses an x86-64 Linux build host. macOS platform-build support ended in 2021; browsing the source on a Mac does not establish that this Android 12 target can be built there.

3.1 Initializing the Build Environment

Install host dependencies using the official setup guide. This is its general Ubuntu package list. Older extras such as libncurses5 from the original article are not necessarily available under the same names on newer distributions.

Android 12’s old prebuilt tools can still require older host libraries. Diagnose the failing tool and use a matching Linux environment; do not treat arbitrary old-library downloads or system-library replacement as a universal fix. Use the toolchain selected by the checked-out branch rather than applying a current Android branch’s JDK requirements.

3.4 Starting the Build

The first full build means a long wait, especially if CPU or memory is limited. Run m for the selected product’s default build. -jN controls parallelism; otherwise the build system selects it. More jobs do not guarantee a faster build and can increase memory pressure.

Interpret helper commands using Android 12 envsetup.sh:

Command Scope
m / m droid Normal selected-product build, not all products at once
m <module> An existing module target; not proof that every flashable image was updated
mma / mmma <dir> Modules in the current/specified directory and their dependencies
croot Return to the source-tree root
m help / hmm Build-target/environment-command help
m clean Clear the configured output directory’s contents; check OUT_DIR first, rather than assuming the current directory’s out/

The branch defines what m all includes; it is not a promise to compile every Android.mk independently. Android 12 Soong’s clean implementation clears the actual output location and preserves its directory. Routine incremental builds do not need a clean each time.

4. Flashing the Device

Use a dedicated test device and match its Pixel 3 XL target, binaries, and artifacts. Bootloader unlocking and the -w option below erase user data; back up first. Enabling OEM unlocking is not itself unlocking. If needed, follow the official procedure: run fastboot flashing unlock in bootloader mode and confirm on the device. Do not casually relock a device running an unverified custom image.

Check adb/fastboot versions and the connected target. Keep the configured envsetup/lunch shell so ANDROID_PRODUCT_OUT points to this build’s crosshatch output. With multiple devices, select the intended serial using -s.

The original adb reboot fastboot enters userspace fastbootd on supported devices, unlike adb reboot bootloader. The flashing tool may change modes for dynamic partitions; see the fastbootd documentation. Do not bypass partition or compatibility checks with --force.

The Android 12 fastboot implementation reads flashall images from ANDROID_PRODUCT_OUT and normally reboots on completion. A second fastboot reboot is not mandatory. flashall is not a universal replacement for matching bootloader/radio firmware; resolve firmware mismatches using the device-specific official procedure.

The top of the old image contains an earlier command error; the later flashall shows OKAY/Finished. That is historical tool output, not current r3 device acceptance. After booting, compare ro.build.id, ro.product.device, and ro.build.type with the built artifacts, then check required USB/display/network functions. Reaching a home screen does not validate all hardware.

I found the AOSP Launcher I had just built pretty ugly and bare-bones. Without Google’s closed-source extras, it looked rather sparse. I much preferred the official Pixel Launcher. That was my reaction to those 2021 builds, not a review of their current versions.

For restoration, select the matching device in Google Factory Images and follow its version/anti-rollback instructions. Restoration can erase data and is not guaranteed to fix every flashing or hardware failure.
