2023 年，公开研究披露了某款 Android App 中的漏洞利用代码和动态下发的 DEX。我想看看这些代码尝试调用哪些系统能力，于是有了这篇文章。当时准备仓促，有些代码没有仔细看；下面保留分析过程，并修正能从截图和 AOSP 源码确认的问题。原始文章和代码链接如下：

  1. 深蓝洞察：2022 年度最 “不可赦” 漏洞
  2. XXX apk 内嵌提权代码，及动态下发 dex 分析
  3. Android 反序列化漏洞攻防史话

我不是安全方面的专家。关于漏洞背景，可以参考 Android 反序列化漏洞攻防史话。本文不复现漏洞链，也不把某个接口调用直接等同于已获得 root。

历史案例，技术复核：2026-10-14。 本文分析的是 2023 年公开材料，不代表该 App 当前版本或所有厂商设备的行为。来源仓库以 6.49 为 APK 示例；各 DEX 的完整下发记录、执行身份、设备系统版本和安全补丁级别并未在本文中建立。截图能说明代码的调用意图，不能单独证明在用户设备上调用成功、收集了哪些数据或已经上传。文中的厂商接口按历史记录保留，当前适用性未验证。

“系统权限”也不是一个统一开关：预装 App、特权 App、平台签名、system UID 与 root 是不同条件。AOSP 中 system UID 为 1000、root UID 为 0；具体操作仍要看 Binder/Provider 权限检查、AppOps、文件访问控制和 SELinux。反射或 @SystemApi 不会自动授予调用权限。参见 AOSP Process（Android 13）、特权权限白名单、SELinux 和 非 SDK 接口限制。

序列化和反序列化是指将内存数据结构转换为字节流，通过网络传输或者保存到磁盘，然后再将字节流恢复为内存对象的过程。在 Web 安全领域，出现过很多反序列化漏洞，比如 PHP 反序列化、Java 反序列化等。由于在反序列化的过程中触发了非预期的程序逻辑，从而被攻击者用精心构造的字节流触发并利用漏洞从而最终实现任意代码执行等目的。

这篇文章主要看 公开仓库 中 DEX 的反编译截图。按可见的调用和目标，大致可以分为下面几类；其中有的操作普通 App 经用户授权也能完成，有的依赖系统或厂商权限，不能一概称为“提权后已经做了这些事”。

  1. 自启动、关联启动相关的修改，偷偷打开或者默认打开：与手机厂商斗智斗勇。
  2. 开启通知权限。
  3. 监听通知内容。
  4. 查询使用事件、配置文件或标识字段；具体内容取决于接口、权限和输入参数。
  5. 修改系统设置。
  6. 整一些系统权限的工具方便自己使用。

另外也可以看到，这个 App 对于各个手机厂商的研究还是比较深入的，针对华为、Oppo、Vivo、Xiaomi 等终端厂商都有专门的处理，这个也是值得手机厂商去反向研究和防御的。

最后我还加上了这篇文章在微信公众号发出去之后的用户评论，以及知乎回答的评论区（问题已经被删了，但是我可以看到：如何评价拼多多疑似利用漏洞攻击用户手机，窃取竞争对手软件数据，防止自己被卸载？ - Gracker的回答 - 知乎 https://www.zhihu.com/question/587624599/answer/2927765317，2023 年写作时记录为 2471 个赞）可以说是脑洞大开（关于 App 如何作恶）。

需要区分同名接口。公开的 NotificationManager.getActiveNotifications() 从 API 23 起可读取调用 App 自己发布的活动通知（API 29 起也包括它以通知代理身份发布的通知）。截图中的跨 App 服务端接口则不同：Android 13 的实现 检查 ACCESS_NOTIFICATIONS、AppOps 和用户范围。截图没有证明样本通过了这些检查。

4. 用户数据

4.1 获取用户使用手机的数据

  1. 文件 ： 35604479f8854b5d90bc800e912034fc.dex
  2. 功能 ：查询一段时间内的使用事件，筛选并整理包名、类名、时间戳和事件类型。
  3. 类名 ：com.google.android.sd.biz_dynamic_dex.usage_event_all.UsageEventAllExecutor

服务名应为 usagestats，不是 usagestates。截图调用 UsageStatsManager.queryEvents，但这不是完整的安装列表或用户全部操作记录。普通 App 也可经用户在设置中授予使用情况访问权限后查询；Android 13 服务端 会检查 AppOps，并在默认模式下检查 PACKAGE_USAGE_STATS。单看客户端 checkPermission 不能替代服务端判定。

系统定义了 Activity、前台服务、屏幕状态等事件，但样本还会筛选数据，不能因为枚举里有某一类型就认定全部采集。查询受时间范围和系统保留期限限制；API 文档 说明事件只保留若干天，Android 11 起用户尚未解锁时可返回 null。

下面是 Android 13 android-13.0.0_r1 中 UserUsageStatsService.eventToString 的事件名称映射；原文错标为 UsageEvents.java。这是服务端调试辅助方法，包含内部事件，不是普通 App 可直接复制调用的 SDK 示例。

4.2 获取用户使用数据

  1. 文件：b50477f70bd14479a50e6fa34e18b2a0.dex
